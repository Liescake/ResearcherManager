# P2 开源复用评估

> 版本：0.1；状态：检索初筛，未授权直接集成。
> 原则：仅在许可证、维护、依赖安全、代码质量和适配度完成审查后，才允许由实施模型接入。

## 1. 初筛结果

| 项目 | 发现渠道 | 初步用途 | 许可证/活跃度/安全 | 结论 |
|---|---|---|---|---|
| NestJS 官方生态 | 官方项目与文档 | API 框架、模块化 | 需以具体版本 LICENSE 和依赖锁定复核 | 可评估 |
| RuoYi-Vue（候选，未集成） | 官方 Gitee 仓库/文档初筛 | Spring Boot 后端 RBAC、日志、代码生成基础 | 候选 `springboot3` / `v3.9.2` / `0e2d75c23c0d7a1fa85f660f06a59a4dd1ba14c0`；MIT 与 LICENSE、NOTICE、SBOM、漏洞、PostgreSQL 仍待本地核验 | 仅候选，不得集成 |
| React + Vite 官方生态 | 官方项目与文档 | Admin Web | 需以具体版本 LICENSE 和依赖锁定复核 | 可评估 |
| Prisma 或 TypeORM | 官方项目与文档 | PostgreSQL ORM/迁移 | 需比较迁移能力、许可证和运行时依赖 | 待比较 |
| React Admin / Ant Design Pro 类模板 | GitHub 初筛 | 管理端组件/页面参考 | 模板质量、许可证和依赖需逐仓库核验 | 不直接复制 |
| NestJS + Next.js + PostgreSQL SaaS boilerplate（如 nova-starter） | GitHub 初筛 | 架构参考 | 需要逐项核实 LICENSE、提交活跃度、默认鉴权和多租户安全；Next.js 也不等于既定 Vite 栈 | 仅参考，暂不集成 |
| 微信小程序脚手架 | GitHub 初筛未形成可信候选 | 学生端启动 | 小程序生态和账号配置差异大 | P3 再验证 |

## 2. 当前决策

- 不复制未经评估的 GitHub 业务代码。
- 首期使用官方框架、官方文档和最小依赖构建，优先避免引入大型后台模板。
- 组件库、表格、图表、ORM、校验库和小程序构建工具必须在 P3 形成依赖清单后逐项记录许可证、版本、来源、风险和替代方案。
- 任何包含默认账号、示例密钥、宽松 CORS、未验证上传、绕过 RBAC 或明文日志的模板不可直接采用。

## 3. P3 引入前检查表

- [ ] 固定仓库 URL、commit/tag、许可证原文和 NOTICE 要求。
- [ ] 检查最近发布/提交、issue 响应、维护者和依赖生态。
- [ ] 锁定版本，执行依赖漏洞扫描和许可证扫描。
- [ ] 审查认证、授权、文件上传、序列化、日志和默认配置。
- [ ] 评估与 TypeScript + React/Vite + NestJS + PostgreSQL 的兼容性。
- [ ] 明确是直接依赖、代码参考还是保留补丁；写出升级和回滚路径。
- [ ] 由上级模型给出“可采用/需整改/不可采用”，再交实施模型接入。
