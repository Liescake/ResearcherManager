## 2. 合规与供应链待核验项

在任何源码复制、依赖声明或版本控制上传前，必须形成可复核证据：

1. 下载指定仓库并确认远程 URL、分支/tag 与 commit SHA 一致；
2. 读取并保留原始 `LICENSE`；若项目或依赖包含 `NOTICE`、第三方版权或许可文本，必须随交付物保留；
3. 生成主项目及传递依赖 SBOM，记录工具、版本、生成时间和输入锁定文件；
4. 执行依赖漏洞扫描，记录扫描工具、数据库/规则版本、结果和处置结论；
5. 核验 JDK、Maven、Spring Boot、MyBatis、认证组件和 PostgreSQL 驱动版本；
6. 审查默认账号、默认密钥、上传、日志、CORS、会话/token、反序列化、SQL、文件访问和生产配置；
7. 验证 PostgreSQL DDL、分页、UUID、时间及时区、索引、事务、锁和字符集兼容性；
8. 记录升级策略、补丁来源、回滚方式和许可证义务。

**门禁：**上述证据不完整时，候选只能用于只读评估，禁止复制源码、加入正式依赖、合并业务迁移或宣称许可证合规。

## 3. POC 准入条件

POC 仅在以下条件满足后开始：

- 本地已核验候选 commit 与许可证原文；
- LICENSE/NOTICE 保留方案已确定；
- SBOM 与漏洞扫描已完成，阻断项有书面处置；
- PostgreSQL 兼容性测试计划和回滚数据库方案已确认；
- RuoYi 源码隔离在 `services/ruoyi-api/`，不覆盖或嵌入现有 `services/api/`；
- 现有 React/Vite 管理端、原生小程序和 `packages/ai-adapter` 的过渡边界已确定；
- POC 范围包含 mock login、角色、`SELF/GROUP/ASSIGNED`、小组查询、入组申请、PostgreSQL 和 AI adapter 健康调用；
- POC 包含越权负向测试，并验证不信任客户端角色、scope、groupId、owner 和授权集合；
- GPT6sol 完成架构/安全审查，GLM5.3 f 完成独立放行。
