# 开发错误记录

用于记录项目实施过程中已确认的错误、影响、根因、修正措施和防复发要求。新增记录必须保留事实依据，不将未验证的推测写成结论。

## ERR-001：未优先评估成熟开源后端项目

- **发现时间**：2026-10-08
- **阶段**：P3 基础工程选型
- **错误描述**：用户最初要求尽量复用成熟 GitHub 开源项目/模板，但项目先行创建了 TypeScript + NestJS 自研后端骨架，没有在动手实现前优先完成 RuoYi 等成熟后台框架的系统评估与 POC 对比。
- **实际影响**：产生了可运行的 NestJS 基础工程和权限策略，但后续若采用 RuoYi，需要重新评估后端技术栈、权限模型、数据库迁移、API 适配和部署链路，带来重复工作与迁移成本；也延后了对成熟 RBAC、数据权限、日志和代码生成能力的复用。
- **根因**：未把“开源项目优先评估”设置为技术实施前的硬门禁；只做了类别级开源复用评估，没有先锁定候选项目、版本/tag、许可证、活跃度、安全、PostgreSQL 兼容性和 POC 验收结果。
- **纠正措施**：暂停直接提交/推送；将 RuoYi-Vue 前后端分离后端作为迁移候选，先锁定具体分支/tag并核验 LICENSE、NOTICE、依赖许可证、漏洞/SBOM和 PostgreSQL 兼容性；先实现登录、用户/角色、小组查询、入组申请、SELF/GROUP/ASSIGNED 负向权限和 AI adapter 健康调用的 POC，再决定是否全面迁移。
- **当前决策**：用户已明确改用 RuoYi，必要时允许重写现有 NestJS 后端。过渡期保留 React/Vite 管理端、原生小程序和 TypeScript AI adapter；不得把 RuoYi 菜单权限直接当作业务资源权限。
- **防复发门禁**：以后新增核心技术栈或大型基础模板前，必须先完成候选清单、具体版本/tag、许可证/NOTICE、维护活跃度、安全扫描、兼容性、迁移成本和最小 POC；未通过评估与 POC，不得进入大规模代码实现。
- **证据**：RuoYi 官方仓库：[https://github.com/yangzongzhuan/RuoYi](https://github.com/yangzongzhuan/RuoYi)；官方文档：[https://doc.ruoyi.vip/](https://doc.ruoyi.vip/)；迁移方案与权限边界已由当前会话审查结论确定。
